Behaviour of the service before and after the code changes made with this documentation round (see docs/design-decisions.md, section 'Changes made').
Each group below was run with docs/examples/probe_service.py against a freshly started service. The original code has a fixed limit of 5 requests per 60 s
(probe run with `limiter --limit 5`); the current default is 60 (`limiter`, which sends 62 requests).
Recorded 2026-10-04 on Linux x86-64 (AMD Ryzen 7 7435HS, 16 threads), Python 3.12.3, fastapi 0.121.2, onnxruntime 1.23.2,
opencv-python-headless 4.12.0.88, numpy 2.2.6, uvicorn 0.38.0, one uvicorn process, client on the same machine.
Detector: the real detector file models/best.onnx (kept outside the repository). Classifier: STAND-IN files from docs/examples/make_standin_models.py, so every class name,
confidence and `uncertain` value below is meaningless (it depends on the average colour of a crop); boxes and detector scores are real.

##### A. Classifier files missing (models/disease_classifier/ has meta.json only)

=== BEFORE
--- health
GET /health
  HTTP 200  {"status":"healthy","service":"ml-inference","version":"1.0.0","detector":"failed","classifier":"failed"}
GET /model-status
  HTTP 200  {"detector":{"loaded":false,"type":null},"classifier":{"loaded":false,"type":null}}
(log of the original code: 'Failed to load detector' twice, one of them for the classifier; /health still says healthy)

=== AFTER
--- health
GET /health
  HTTP 200  {"status":"degraded","service":"ml-inference","version":"1.0.0","detector":"loaded","classifier":"failed"}
GET /model-status
  HTTP 200  {"detector":{"loaded":true,"type":"YOLO_ONNX_Inference"},"classifier":{"loaded":false,"type":null}}
POST /detect  cardinal-tetra-school.jpg, classifier missing
  HTTP 200  status=success count=29 message='Found 29 objects'
POST /analyze cardinal-tetra-school.jpg, classifier missing
  HTTP 500  {"detail":"Classifier model not loaded"}
(these two requests were not sent to the BEFORE service: it reported its detector as failed too)
